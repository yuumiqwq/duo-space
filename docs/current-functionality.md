## 身份与进入教室

网站是固定自习房间，使用身份识别码登录，没有公开注册或由用户创建多个房间的界面。服务器将识别码的 SHA-256 摘要映射到身份 ID，同一识别码在不同设备上仍对应同一成员；未配置身份映射时保留旧共享密码对应的 `legacy` 身份。

登录成功设置有效期 30 天的签名 Cookie，带有 HttpOnly、Secure 和 SameSite=Lax 属性。页面入口会验证登录，业务接口另按各自需要核对身份与成员权限。昵称、活动内容和滴答连接绑定服务器身份，浏览器设备 ID 用于区分同一成员的不同设备；昵称接口只补充尚无昵称的记录，没有常规改名流程。

进入教室前会等待身份资料、必要图片解码与字库加载，并读取已删除画板记录和教室成员资料。加载中显示当前名字及等待状态，失败提供重新加载；成功请求复用缓存，失败或超时后可以重新请求。附件链接登录成功后仍回到原附件路径，不强制先进入教室。

安全出口停止本页的采集与连接，然后跳转登录页。当前出口没有清除服务器签名 Cookie，因此它的作用是退出本页房间，会话仍可能有效。

## 教室与座位

主区域在默认黑板、协作画板与投影之间切换，右侧提供“传纸条”和“今日任务”。默认黑板显示上海日期与公共任务标题，日期在午夜及页面重新可见时刷新；容纳的任务条数按实际文字高度计算，长内容可滚动。

两个个人桌位分别使用平板和笔记本。同一身份的多个在线设备归入同一个成员位置，离线成员的桌面外壳仍保留。本人可修改“我正在”的活动内容，按 Enter 保存并通知其他设备，最多 80 个字符且受实际单行宽度限制；同桌的内容只读。

设置包含“通用”中的座位选择和“消息提醒”中的设备通知开关与测试。两名不同成员均已占据座位时，本人可以选择平板或笔记本，保存后同时更新双方位置，无须另一方批准；保存目标位置相同不会再次交换。座位未保存内容属于本次弹窗草稿，关闭即放弃，保存失败保留草稿，保存过程中禁用关闭。设备通知按钮直接操作当前设备，不随座位保存或取消。

桌面任务板打开协作区，文件夹打开云盘，粉笔杯创建画板。双人日历目前仅有物件和按钮，没有可用的日历交互；主题配色、背景上传和字体选择没有正式设置入口，页面沿用已确认的固定样式。黑板装饰的每日更换及成员点选同步尚未接入。

## 今日任务与滴答连接

### 连接与读取

成员通过 API Token 连接滴答，服务器验证当前功能必需的收集箱读取权限，再将令牌加密保存到该身份，不逐个扫描其他清单。断开连接删除本站保存的令牌，不删除滴答任务；旧浏览器加密令牌仍可迁移到身份记录。连接诊断只返回字段类型和数量，不包含令牌或任务正文。

本人今日任务为空且尚未连接时显示连接入口。连接弹窗保留刷新及断开控件，但正式设置页没有独立的滴答管理入口，不能假定用户随时能从设置重新打开连接弹窗。

今日任务合并滴答未关闭清单和收集箱的数据，并按任务 ID 去重。收集箱编号从该账户实际响应确定，不使用其他成员的编号；空收集箱直接返回空列表，不等待可选清单资料；只有创建或按收集箱定位任务时才补查具体编号，仍无法解析时使用原有错误反馈。单个清单或清单目录读取失败时，保留其他成功结果并给出反馈；教室今日任务保留失败或未覆盖清单的上次数据，成功读取的清单仍按新结果处理任务移出与删除。目录和收集箱均明确返回授权失效时，接口返回未连接状态。今日任务的完成历史与清单读取并行，同一页面进行中的读取可复用，外部写入后若仍有较早读取，会补做一次新刷新。

### 教室今日任务的日期规则

教室按北京时间早上 06:00 换日，今日任务包含当前窗口的任务，以及窗口之前仍未完成的过期任务；定时任务窗口包含起点、不包含次日 06:00。开始与结束时间都有有效值时取较晚者，只有一个有效时间则使用该时间；无有效日期及未来任务不进入当前列表，纳入今日任务不修改任务原日期。本人列表、同桌列表与服务端快照使用相同筛选规则。

全天任务按上海日历日期归属，并持续显示到次日 06:00。例如 9 月 12 日凌晨 02:00 仍显示 9 月 11 日的全天任务，9 月 12 日 06:00 才切换到 9 月 12 日；带时区的日期值先转换到上海日期，不能直接截取 UTC 字符串的前十位。

符合当前窗口的已完成与未完成任务一起显示；窗口之前的过期任务在本次 06:00 窗口内完成后，也保留到下一次 06:00，历史已完成任务不因此持续带入。点击完成后先显示勾选，服务器确认后保留勾选和删除线，失败则恢复；刷新或其他设备读取时仍可从保存的快照恢复本站当天完成记录，同一重复任务进入不同日期后不会沿用上一次勾选。滴答完成历史读取失败时保留本站已知记录，无法据此保证外部完成历史绝无遗漏；未完成的过期任务会继续带入之后的今日列表。

本人卡片允许完成自己的普通任务；关联流程中，审批方可以直接完成，认领方不能借此跳过提交和审批，流程尚未确认完成时会提示到任务板处理。同桌卡片只读，多个设备传来的同桌任务按身份合并，当前侧栏仅展示第一组其他身份的任务；本人自由小记最多 24 个字符、不能换行，按 Enter 保存并同步，同桌小记只读。

“新”按钮仍用于查看其他成员通过共享待办接口加入的任务。关闭弹窗时仅将实际展示过的条目标为已查看，失败保留弹窗；相关列表在可见页面每 5 秒及网络恢复时刷新。

### 保留接口的不同日期语义

`/api/ticktick/tasks` 的普通 `view=today` 包含截至今天的未完成任务，因此会包含逾期；`view=week` 包含截至七天后的未完成任务，也包含逾期。无日期视图和 `view=today&exact=1` 的日历日期筛选另有实现，正式教室使用 `classroom=1` 的 06:00 窗口并带入过期未完成任务，保留上述当天完成显示规则。修改筛选逻辑时应分别核对这些入口，避免把不同规则合并。

## 公共任务板与认领

任务板上方显示服务器公共便签，下方按成员展示滴答收集箱的有日期和无日期任务。这里的成员栏限定为收集箱，与今日任务读取全部未关闭清单的范围不同；已进入流程的任务移到其他清单后，服务端仍按精确编号查找已有任务。

公共任务通过加号创建，保留原发布者身份，后续由其他人修改也不会改变发布者。公共便签和成员任务均点击标题进入同一个工作流程详情弹窗，公共便签的省略号也进入该弹窗。未认领时左栏只显示原任务所属成员或公共发布者审批，流程事件列表为空，右栏使用与已认领任务相同的详细设置；不会显示认领者或提交审批入口。任务被认领后，详情转为对应流程，记录从认领事件开始，认领前的普通修改不补入流程历史。

认领既可由本人操作，也可通过拖动安排另一个已连接滴答的成员。原任务属于自己时不能再按“认领他人任务”处理；跨成员认领会检查双方实际账户是否相同，带父子任务关系的个人来源会被拒绝，已有流程或正在处理的任务也不能重复认领。

认领表示默认由认领者负责完成，关联副本用于其在滴答中安排日期，认领本身不表示已经开始执行。新认领与没有执行安排的历史认领统一列为“已认领”，不根据认领日期、优先级或旧的内部建立状态自动选出执行任务；原任务关系及认领者印章继续保留。

| 来源与操作 | 建立后的任务关系 |
| --- | --- |
| 认领他人的个人任务 | 原任务保留，在认领者收集箱创建关联任务，原所属成员负责审批。 |
| 认领他人发布的公共任务 | 公共卡保留，只创建认领者的滴答任务，发布者负责审批；发布者只需保留网站成员身份，不以其滴答连接或收集箱读取成功为前提。 |
| 发布者将自己的公共任务放进自己的收集箱 | 成功后移除公共卡，留下普通未完成任务和操作记录，不进入审批，也不自动完成；之后仍可被其他成员认领。 |

任务便签与成员任务卡片采用相同的时间显示规则：优先使用有效截止时间，没有有效截止时间则使用有效开始时间；定时任务超过该时刻显示“已过期”，全天任务在北京时间次日零点起显示“已过期”。未过期任务沿用相对日期及时间，无日期任务不显示时间标签；详情设置保留原始日期值。

公共便签从图钉位置拖动，成员任务从非交互区域拖动；移动约 7 像素后出现跟随副本，列表边缘支持自动滚动。键盘可以用空格或 Enter 拿起，方向键选择成员，再按 Enter 放下，Esc 取消。目标成员必须已经连接滴答且读取正常，公共区不是退回目标。

放到同一成员的有日期任务之后，可将展示日期调整为前一条任务的上海日期，保留已有时分与持续长度；无日期任务只补截止日期。跨成员认领携带同样的日期参照，服务端检查参照任务的版本；放到无日期栏不会自动删除已有日期。

所有登记成员可以编辑未认领任务及流程详情，未连接滴答本身不妨碍这些被允许的操作。未认领任务的普通删除接口也允许其他登记成员操作，完成操作则仅限原任务所属成员或公共发布者；已经进入流程的任务不能用普通编辑、删除或完成接口绕过流程。

## 流程审批与删除

任务板“工作流程”入口不显示红点，数字角标只统计“自己的执行中”和“对方的执行中”两组里的待审批任务，每项任务计一次。详情更新、催办及同步错误不增加这个角标；查看详情不消除待审批计数，审批通过或打回后才移除。卡片原有“有更新”状态继续保留，打开详情并成功保存已读后恢复原状态。

主界面任务表入口的数字角标统计未读的新公共任务、执行中有详情更新或待审批的任务，并包含本人已认领任务的未读他人修改与审批打回；同一任务同时符合多项条件时仍只计一次。本人认领的任务无论是否安排执行，只要其他成员在网站修改了详情或审批者打回，对应任务卡片和公共便签就共用同一份红点状态；自己修改、同步错误和催办不触发该红点。红点不会因看见任务板、勾选执行安排或关闭打回弹窗而消失，必须从任一入口打开该任务详情并成功保存已读，两处红点随之一起清除，后续另一项修改或打回可再次出现。本人未安排执行的任务只有这些红点计入主界面角标，对方未安排执行的修改不增加自己的角标；归档记录不计入。未认领的新公共任务继续沿用可见后已读规则，已认领公共任务的原公共提醒与流程提醒一起在详情中标为已读；待审批计数则保留到审批状态改变。

任务表关闭时，现有五秒轻量轮询额外返回未归档流程的编号、来源、认领者和状态摘要，不读取滴答，也不传输完整详情或事件历史。主界面角标使用版本较新的摘要或任务快照，因此未安排执行的任务更新、提交审批及审批完成都能更新角标，无须先打开任务表；旧响应不能覆盖较新的状态。

### 阶段与权限

工作流程页面只显示“自己的执行中”和“对方的执行中”两个分组，按认领者身份归属，与当前成员是否负责审批无关；每组内待审批任务置顶，同一审批状态下按优先级从高到低排列，同级按认领时间倒序。待审批卡片显示阶段标签，有未读详情设置修改或审批打回时显示黄色“有更新”，仍待审批时同时保留待审批标签；未读情况不改变排序。仅已认领但尚未安排执行的任务不进入这两个分组，仍可从任务板进入详情；本人任务也可在安排执行弹窗中选择。完成和用户明确删除的流程进入归档，归档先显示有未读的流程，再按更新时间倒序；滴答任务意外缺失仍保留原阶段和原执行安排。

点击标题旁的“安排执行”打开二级弹窗，原工作流程页面保留在后方。弹窗只列本人认领的可安排任务，依次显示“执行中任务”和“已认领任务”，第一组仍将待审批置顶；不列对方任务或归档任务。卡片右侧沿用圆形复选框，原执行任务和待审批任务初始勾选，待审批任务不可取消勾选；未读圆点保留，弹窗内不显示“有更新”文字。勾选期间不因草稿选择改变分组，点击“保存”成功后关闭二级弹窗并更新原列表，保存失败保留弹窗和选择；安排版本发生冲突时按已有错误提示关闭并重新安排。关闭或按 Esc 只放弃二级弹窗的未保存选择并返回原页面，保存请求进行中不能关闭。安排仅改变网站的执行标记，不调整滴答日期，也不另加时间轴记录。

工作流程和安排执行的任务卡片共用任务板成员卡片的白色平角外观，左侧使用相同优先级色条：高为红色，中为橙色，低为蓝色，无优先级不显示色条。时间沿用任务板的日期、具体时刻和过期判断，无日期时不生成时间文字；长标题可换行，窄屏保留状态和选择控件。流程卡片点击查看详情，安排卡片点击勾选，不接入拖动。

首次启用时，仅初始化已经存在认领关系的流程：已提交审批且尚未通过的任务设为执行中并保留待审批阶段及材料，其余已认领的未完成任务初始不执行。已进入审批完成同步的任务继续保留相应名额，完成后释放；无人认领的公共任务及已归档记录保持原样。初始化只补充缺省的执行字段，之后用户保存的安排在刷新、重启及后续部署时保留。

每位认领者最多同时占用三个执行名额，可以少于三个或不选择执行任务。尝试勾选第四项时保持原选择，并短暂显示半透明提示“执行中任务最多3个”。待审批期间继续占用名额，不能通过取消勾选腾出名额；被打回后保留执行资格，可继续处理或在安排中暂停。审批通过并完成、直接完成或明确删除后释放名额，完成同步尚未确认时继续保留。旧的待审批任务和提交材料照常保留并计入名额；若历史待审批项已经超过三个，先处理这些审批，不能新增执行项。

执行安排由服务端一次保存，并检查当前成员身份、任务归属和三项上限。它使用独立版本防止两个设备覆盖对方的安排，普通催办或内容编辑不使安排版本过期；提交、打回及名额释放会更新安排版本。相同请求重复到达只返回已保存的结果，不会重放旧安排覆盖新选择；提交接口及提交附件入口同时校验执行资格，旧页面也不能绕过安排直接提交。

| 操作 | 允许的身份与结果 |
| --- | --- |
| 提交完成 | 只有已安排为执行中的任务允许认领者提交说明和附件，进入待审批并继续占用执行名额。提交只保存网站状态与材料，不读取或修改滴答。允许空说明且无附件；外部提前勾选不额外产生补交要求。 |
| 通过或打回 | 原任务所属成员或公共发布者在待审批时操作。通过完成已有的关联任务并归档；打回只保存网站状态与材料，之后由认领者重新提交，不读取或修改滴答。 |
| 直接完成 | 原任务所属成员或公共发布者可在未完成流程中直接结束任务，无须先等待认领者提交。 |
| 修改详情 | 登记成员可编辑可修改字段；已删除或删除处理中禁止编辑。提交后修改不会自动打回，也不会抹去已提交材料。 |
| 删除流程任务 | 发起方或认领者使用各自删除入口，二次点击确认。当前两个入口均先移除公共卡并进入“已删除”归档，再分别尝试删除双方关联的滴答任务，保留事件与提交文件。 |

提交和打回允许在关联任务缺失、滴答连接异常或详情同步未完成时进行，附件上传使用相同的网站身份与阶段规则；成功保存不因已有的外部状态提示而被判为失败，同一命令重放也不触发滴答同步。审批使用明确的人工决定，提交后任务内容或滴答版本标识变化不会自动禁止通过，完成时保留任务当时的内容。详情写入仍有版本保护，重复任务已经进入后续日期时也继续保护，不能把“提交后允许编辑”理解为所有并发检查均已取消。

删除范围覆盖创建中至已完成的流程。服务器接受删除后先持久保存网站端的“已删除”归档并释放执行名额，再分别尝试删除已有的双方滴答任务，某一侧失败不妨碍尝试另一侧。外部操作在网站写入队列之外执行，不阻止读取已归档状态或保存其他网站操作；保存外部失败提示时重新读取最新网站记录，避免覆盖并发操作。

滴答明确返回删除成功后直接结束该侧处理，不再额外读取确认；查找失败、删除响应丢失、删除接口返回路径不存在或其他删除错误，统一返回“滴答清单中删除失败”，网站流程继续保持“已删除”。接口返回网站归档已完成的 200 响应，并在已有错误区域显示这条提示；返回列表后仍可在归档中查看。没有发起方滴答副本的公共任务正常跳过该侧；旧公共任务仍保存发起方副本编号时，按该历史编号查询，不能仅因目前公共任务不创建副本而忽略它。完整查询确认已经不存在的任务无须再次删除；任务进入后续重复日期时保留对应外部任务并显示上述失败提示。

删除请求保存双方任务编号、所属账号、查询或删除阶段及提供方返回信息，保留原始结果。刷新、服务重启以及同一命令重放都不会再次尝试滴答删除；服务在本地归档后中断时，也不恢复未完成的删除写入。后续已登录请求触发维护时，对仍有删除错误或结果未确认的归档流程按原编号只读核对，每轮最多三个并按失败次数延长间隔至五分钟；已明确删除成功或查明不存在的一侧沿用其证据，其余关联任务全部确认不存在后清除旧错误。仍然存在、已进入后续重复日期或无法完整读取时保留错误，同时记录最近核对结果，不改写流程事件，不以收集箱没有该任务推断它已删除。

滴答的原清单任务详情接口在删除成功后仍可能返回状态为未完成的残留记录，这一点已经通过独立临时任务复现。因此，判断关联任务是否存在时使用当前未完成列表与有范围限制的完成历史；按原清单读取到旧详情本身不再构成任务仍存在的证据。旧删除错误会通过后续只读核对更新，另一成员的实时状态仍须由其连接返回，不能用当前账号查不到对方任务来推断删除成功。

已归档且仍有删除错误时，发起者或认领者可在详情中点击“重试删除滴答副本”，再确认删除剩余副本。每次明确确认保存独立回执，只查询原账号下对应的任务编号，跳过已经确认不存在或删除成功的一侧，并继续保护后续重复日期；不会重新建立任务，也不向时间轴追加错误或恢复事件。同一确认请求重放及服务重启不再次发起删除，只保留核对入口。错误报告分别保留原始删除结果、每次明确重试及最新核对结果；删除响应丢失时，本次操作会补查是否仍存在。

旧版本已经接受但一直等待确认的删除请求，在后续维护中先完成网站归档并清除旧重试标记；已有回执不足以确认外部结果时保留删除失败提示，再进入上述只读核对。此前已经完成的旧版单侧删除记录保持原有流程阶段和范围，只清除遗留等待标记，不扩展外部删除范围。

### 任务板读取与后台维护

进入教室后即在后台预加载一次任务板数据，先读取网站保存的公共任务、流程记录和成员资料，这个响应不访问滴答，也不等待后台写入队列。各成员的收集箱随后独立读取并分别显示，一人的慢请求或读取失败不阻止另一人的列表；打开任务板时沿用已有数据和仍在进行的读取，尚未读到任务的成员显示已有的读取图标。关闭任务板保留当前页面的预加载结果与进行中的请求，不持续轮询收集箱；离开教室、切换身份或刷新整个页面后不保留这些内存数据。

任务板打开期间每五秒独立刷新网站记录，成员任务按原有十五秒周期刷新。一次成员读取尚未完成时不重复发起全量刷新；同一服务进程里针对同一成员同时发生的收集箱读取复用一个请求，后续主动刷新仍会重新获取。再次刷新时保留当前已显示的成员任务，读取失败会在该成员栏显示原有错误提示并停止读取图标，保留上次成功的数据；成员断开滴答连接后清空其列表。操作完成后先读取网站记录，再按影响范围刷新成员收集箱；提交、打回、催办、执行安排及公共任务本地操作不触发滴答列表刷新。轻量轮询使用各成员的外部任务变化摘要，仅相关变更触发其收集箱和本人今日任务刷新，不再对每一次网站版本变化扫描滴答；修改滴答的操作或离开教室会取消旧读取结果，纯网站操作保留正在进行的预加载；延迟返回的数据不能覆盖更新的流程或恢复已删除便签。

预加载只把第一次读取提前，最新收集箱内容仍依赖滴答响应；进入教室后立即打开任务板、首次读取失败或整个页面刷新时仍可能需要等待。页面侧网站记录请求最多等待 8 秒，单个成员请求最多等待 35 秒，超时显示已有错误提示；服务端每次滴答请求最多等待 15 秒，空收集箱展示无需查询额外清单资料。这些时限来自实现，不能视为真实账户的加载耗时测量。

成员任务拉取成功时，活跃工作流程的详情同步采用认领者当前滴答副本的设置，并更新对应公共便签，后续纯网站轮询不会再显示旧详情；后台找到已移至其他清单的认领者任务时也会更新详情。未认领的公共任务仍只存在于网站。拉取期间若网站接受了新操作，旧读取结果不能覆盖新设置；已有待写入修改、完成决定或恢复操作时，保留已接受的请求，不用滴答旧值替换。已归档记录和重复任务的后续周期不导入此刷新，普通读取也不伪造网站修改事件。

已登录成员读取收集箱、完整快照或轻量版本接口时，服务器在响应后先继续处理到期的待处理流程，再核对其他活跃流程并发送通知，旧的待确认删除先在本地归档，其他已接受的完成或修改请求也优先于无关的慢查询。轻量版本查询也能触发这轮维护，任务板无须一直打开；同一服务进程中的并发请求与独立调度器复用正在运行的维护任务，完整检查与仅恢复待同步操作分别保留至少 15 秒间隔，避免周期恢复阻止网页触发完整检查。旧删除请求的本地归档不受原重试时间或单轮名额限制；其余流程恢复按重试到期时间排序，单轮至多处理三个项目，尚未获得恢复机会的请求不会因较早记录反复失败而长期排在后面。关闭所有页面后，正式服务仍继续恢复已保存操作，规则见下文独立调度说明。

普通任务保存详情时立即尝试写入滴答，并在写入前持久保存编辑原设置、本次修改意图、完成状态和父任务关系。首次写入失败后，后台每轮核对最多三项，同一未解决操作至少间隔一分钟，并优先核对尚未检查的项目；任务仍未完成且本次修改已生效时直接结束等待，否则按同一套字段合并规则继续，保留未修改字段上的新内容。重试前保存间隔记录，重启不会立即重复写入，手动继续沿用同一修改依据；同组设置有冲突，或父任务变化、完成、缺失、读取失败时保留错误。旧记录缺少修改前设置时仍只读核对，不能自动补造依据；重试读取当前任务列表，不能依靠删除后的残留详情继续写入。错误报告保留最近核对结果与自动重试结果，读取或复制报告本身不触发外部查询及维护。

远程操作按任务或流程分别排队，仅最终文件保存使用共享短队列；不同任务的改动合并保存，同一任务出现并发改动则拒绝旧结果，保留已持久保存的重试依据。提交、打回和删除归档使用网站队列，不等待同流程的远程请求；较早的后台结果不能覆盖新阶段或使归档任务重新出现。执行安排和通知的版本独立合并，未提供跨进程事务保证。

打开任务板不再先发送单独的旧记录迁移请求。网站记录、单个成员与轻量版本读取均在响应后检查和处理旧记录迁移，首次迁移也不阻止这些读取；为兼容旧调用，未指定分段参数的完整协作读取仍先完成迁移检查。部署启动及健康检查不触发迁移。

### 外部勾选与恢复

已保存具体任务编号和清单编号时，读取详情和发送删除只需本地账号凭据，不先读取收集箱。关联任务存在性核对则先读取全账号当前未完成筛选，按同一编号命中后读取实际清单中的详情；未命中且筛选已达上限时，逐清单读取当前任务列表，并包含可能不出现在普通清单目录中的收集箱，不用原清单的残留详情代替当前列表。少量完整筛选与完成历史查询不依赖收集箱解析，因此旧任务缺少清单编号或后台收集箱失败时仍可核对；创建任务及使用收集箱别名的请求仍须解析其编号。

账号凭据与收集箱缓存分别管理，重新连接或断开账号后不能继续使用旧凭据缓存。提供方短期上下文最多缓存 15 秒的账号查询，相同令牌的进行中读取也可共享；传输层请求结束后不另作响应缓存。写入前后使相关进行中读取和提供方缓存失效，写入前发出的旧列表不能重新填入缓存。不完整查询、列表格式错误或完成历史已达上限时保留未知状态，不能判定任务已删除。

后台核对关联任务时，以网站当前阶段和已保存的完成决定为依据。网站仍未完成且没有待执行的完成决定时，发起方原任务与认领者副本在滴答中被提前勾选，都按原 ID 恢复为未完成，保留当时的任务内容和已有审批材料；审批通过、发布者直接完成或正在继续完成同步时，已经完成的关联任务保持原样，不先取消再重复勾选。外部勾选本身不会批准或结束流程，也不会生成补交要求、时间轴记录或未读通知。正常恢复不显示说明或恢复进度，写入失败保留内部回执并按间隔重试。

任务查找先确认未完成任务，未命中才使用已完成证据或查询完成历史。未完成筛选最多返回 200 项，仅在返回满 200 项且未命中时继续按清单定位准确 ID，避免对完整的少量结果再逐清单查询。完成历史只查询网站发布日期当天零点起的记录，按北京时间计算并包含起点，一次最多 200 条，不继续查询更早记录或扩展分页；满 200 条且未命中时保留未知状态，不能判为删除。公共任务保存首次发布时间，旧任务从原创建操作补回；无原发布记录时使用流程最初建立日期，个人来源也使用网站流程建立日期，均不使用任务安排日期。未查全、限流或响应格式错误只作为读取错误。重复任务已经进入后续日期时继续保护，不恢复或完成后续实例。

两类查询都完成且未找到预期关联任务时，网站保留原任务、原阶段和提交材料，暂停依赖该任务的审批通过或直接完成，提交和打回仍可正常保存。在流程记录末端、时间轴之外只显示一行红色小字“该任务已被删除”，不增加事件、数字角标或通知。后续正常读取重新找到同一 ID 并完成状态核对后，提示自动移除；不会根据同名任务擅自替换关联，也不会自动补建任务。原本没有发起者滴答副本的公共任务属于正常情况，缺省副本继续跳过；个人来源中曾明确存在的原任务被删除，则同样显示该提示。

创建复用本轮已读取的收集箱，保存滴答实际返回编号并进行一次内容确认，调用方直接使用确认结果；普通详情修改复用本轮版本检查结果，写入后确认一次。多侧修改或完成在前一侧写入后仍重新读取下一侧，避免跨外部写入沿用旧状态；重试也重新读取。创建请求先保存尝试状态，滴答返回的真实编号保存为后续查找依据。已收到编号的认领也使用上述查找和勾选同步，包括创建后已移动或提前完成的任务，完成核对后继续原流程。创建结果未知时，仅接受创建前不存在且内容相符的唯一候选，其他情况继续等待核对，不重复创建或误报删除。旧的显式恢复接口仍保留，但页面不再提供缺失任务恢复按钮；旧请求有独立的异常次数检查，不能借重放旧请求再次建立副本。

副本内容核对兼容滴答返回的两类等价表示：没有重复规则及提醒的全天任务，只设置开始日期、只设置截止日期与两者为同一天均视为同一日安排；复制检查项时忽略滴答重新分配的检查项编号。检查项顺序及其余字段仍逐项核对，实际内容、勾选状态或日期变化仍会阻止创建确认。该比较不改写网站或滴答字段，任务版本仍包含原始日期及检查项编号，用于防止过期编辑覆盖新状态；定时任务、重复任务和带提醒的任务不适用单日期等价规则。

### 完成决定与失败恢复

通过或直接完成的请求通过身份、流程阶段及版本等检查后，服务器先保存完成决定；审批通过时同时保存评语和附件引用，再开始关联任务查询。查询失败不会仅因点击按钮就将流程标为已完成，尚未确认的认领继续保留原执行安排，待审批流程仍保留“待审批”；此时也不提前追加通过或直接完成事件。决定已经落盘，服务器重启后仍可在后续维护中继续，等待期间不会把已完成的滴答任务取消勾选。

关联任务核对成功后进入完成同步，并追加一次对应操作事件，保留原提交材料及审批评语；已完成的关联任务直接沿用该状态，所有必要任务确认完成后才归档。意外删除仍暂停推进并保留红字提示，重新找到原任务后继续；流程仍处于待审批且允许打回时，发起方可用后续打回请求撤销尚未推进的决定，打回本身只保存网站状态，不等待关联任务核对。已经进入完成同步的流程不能再用打回撤销，整项删除则按删除流程处理并清除待执行的完成决定。

流程弹窗也会重试尚未确认服务器是否接受的操作；已归档删除命令重放只读取归档结果，不重新尝试外部删除。命令 ID 防止重复执行，命令签名防止同一 ID 被用于不同操作，流程版本与普通任务版本用于避免旧页面覆盖新状态；旧版本在保存决定之前返回失败的请求没有可靠服务端记录，不能凭当前任务状态推断用户曾批准。

自动检查覆盖同一编号恢复、无发起者副本以及直接完成时不反复勾选，并模拟关联任务查询阻塞、完成决定保存后查询失败和服务器重启。真实任务当前是否已恢复仍需已登录的线上读取结果，模拟检查不代表真实滴答验收；此前的 `diagnoseWorkflow` 参数仍未恢复，不能将其当作只读诊断入口。

## 详情编辑与附件

### 详情编辑

任务详情支持标题、说明与时间，并提供优先级、重复规则、提醒和标签。时间编辑固定使用上海时区，勾选“全天”后只选一天即表示这一天的全天任务；开始和结束选为同一天也按单日处理。单日任务在表单中只显示一个日期，改这一天会同时更新滴答的开始与截止字段，清空这一天会清除整个日期设置；选择不同的结束日期则设置跨天范围，开始为 00:00，结束为 23:59。已有非预设的重复及提醒选项会保留，不因打开界面被改成默认值。任务复制或更新保留原检查项、任务类型及重复计算方式，详情界面没有开放所有这些字段的编辑。

新建任务和没有日期的任务默认勾选“全天”，已有具体时刻的任务保留原状态。无日期旧任务的默认勾选只影响日期编辑；仅打开详情或修改标题不改写其原始全天标志。全天模式下只选开始、只选结束或两者选择同一天，都按上述单日表示同步。

标题上限 500 字，说明上限 10000 字，标签或提醒各最多 30 项、单项最多 200 字；日期需有效且结束不能早于开始。未认领和已认领任务共用详情设置，浏览器提交实际改动与编辑时的完整原设置 `baseFields`，并附原内容核对标记。服务端核对基准与任务阶段后合并互不冲突的修改，例如网站改日期而滴答改说明时保留两者；双方改为相同值也可确认。日期、全天、时区、提醒及重复规则按关联设置核对，任务类型与检查项为另一组，避免分别合并后改变含义。同组出现原值和目标值以外的设置时暂停覆盖；草稿保留输入，可采用最新内容或保留自己的修改。完成状态与父任务关系变化仍受保护，旧客户端没有基准时沿用原版本检查；完成、删除和审批命令不放宽版本规则。普通任务修改只保留请求回执用于恢复与防重复，不创建流程事件。

流程详情保存后立即尝试修改关联的滴答任务，网站先持久保存本次修改，直到关联任务内容确认一致才结束待同步状态。每次保存立即追加一条“修改了详细设置”，记录相对于上一次网站设置的字段变化；上一项尚未同步时再次保存，也分别保留两次修改。后台同步、重试和后续保存不会改写旧事件的内容，错误不进入这类历史记录。历史事件曾被写成通用同步提示时，能找到对应待同步修改摘要的沿用该摘要，否则仅保留修改者、时间和操作；旧版本已经覆盖掉的具体差异无法由当前任务反推。

详情尚待同步且没有错误时显示同步指示；已有请求错误或服务器同步错误时，在时间轴外显示错误并停止该指示，登记成员可用“重试同步”继续原修改。首次写入前保存原设置和本次修改意图，后续重试使用同一基准，保留未修改字段上的新内容，并允许本次修改部分生效后继续。流程先核对所有关联副本，再写入合并后的设置；任一副本存在同组冲突就暂停，不根据最后读取的副本猜测覆盖。任务状态变化或旧请求没有原设置依据时继续保留原保护；重试不增加修改记录。

正式 Node 服务每轮处理结束后等待 15 秒，再检查到期的待同步操作；没有登录页面请求时仍运行，进程重启后从持久记录恢复。流程沿用最长 5 分钟的退避，普通修改沿用 1 分钟核对间隔，每轮各处理最多三项。调度与网页使用同一实例、串行队列及操作回执，一个维护阶段失败不阻止其他阶段和提醒发送。后台只恢复已接受的操作，不增加全量收集箱轮询或自动重复删除；完整关联检查仍沿用网页请求入口。

处理前通过正式网址 `/api/access/runtime` 核对实例编号，部署候选、未启用正式路由的实例和无法确认正式网址的实例都不处理队列。该公开只读接口只返回随机实例编号、运行标志与最近一轮处理时间，不返回任务或账号数据；接口被读取不触发维护。普通任务与流程的同步错误均通过现有异常入口提醒，同一未解决事件保留一个提醒编号，恢复后失效，错误不增加正常流程记录或执行角标。

详情设置因版本冲突暂停时，登记成员可点击“以网站设置同步”，再点击“确认以网站设置覆盖滴答”，明确采用已保存的网站目标设置。确认绑定当前流程及其版本；页面切换任务或版本变化后须重新确认。服务端为原修改重新获取关联任务基准并继续同步，保留已有修改事件；同一确认命令重放沿用该基准，不能再次覆盖后来出现的第三种字段值，也不能触发后续另一项修改。已删除、任务缺失或非版本冲突的错误不提供此操作。

新选择的单日全天任务直接保存为相同的开始与截止时间，均为所选日期的上海时间 00:00，第一次写入滴答就使用这组字段；包含提醒或重复规则的新日期选择同样如此。该表示与实际滴答单日任务的返回形式一致，表单仍只显示所选的一天。具体时刻模式继续分别设置开始和结束，打开已有任务或仅改标题等其他设置时保留原始日期；不批量改写历史任务。

旧的普通全天单日期请求在发送前转成同一天的两个字段，成功核对继续使用原有受限等价规则，旧请求本身与历史记录保持不变；有提醒或重复规则的旧请求保留原表示。已移除“先发送单字段，回读未生效后再换成双字段补发”的日期处理。清空已有日期时，更新接口发送滴答的清空值 `1970-01-01T00:00:00.000+0000`，因为发送 `null` 会保留原日期；网站仍保存 `null`，不把清空值作为任务日期显示。报告记录实际发送的有限字段，写入后仍须回读确认设置已生效。

详情写入遇到临时服务器错误、传输中断或滴答的并发写入拒绝时，在同次保存中等待 250 毫秒后读取当前任务，已生效则直接确认，否则合并互不冲突的设置后补发一次；发现删除、完成或同组冲突时不盲目覆盖。写入成功但首次回读内容尚未一致时，也会稍后再读一次，不立即重复写入，最终须与本次发送的设置一致。授权失败及限流不会立即重发；仍未完成的请求保留错误和恢复记录，由后续后台处理。这些恢复路径已模拟检查；2026-09-17 用户确认此前报告的三条线上异常均已消失，未据此推定所有任务或接口故障都已验证。

错误区域提供“复制错误报告”，读取 `/api/room/tasks?workflow-diagnostic=<流程ID>`。此入口要求已登录的登记成员，只读取指定流程的本站记录，不读取滴答或触发后台维护。报告包含流程标识、待写入的日期及优先级、失败阶段和版本比较；详情同步失败时另保存写入前、写入响应与回读的有限字段，删除故障包括双方关联编号、原始失败及最近只读核对结果，不记录任务正文、访问令牌、请求头或无关任务。待同步修改最多保留六次尝试，保留最早失败及最近五次；后续设置接续这些证据并分别保留对应修改编号和请求字段，成功同步后清除待同步尝试。旧故障首次失败时未记录的证据不能补造。浏览器剪贴板不可用时显示可选取的报告文本；用户可将报告粘贴给 Codex 排查，网站没有自动唤醒 Codex 或自动提交代码修复的通道。

普通任务的待同步修改在恢复入口同样提供“复制错误报告”，使用 `/api/room/tasks?operation-diagnostic=<操作ID>`。报告包含目标日期、优先级、原请求版本及最近一次后台核对的当前字段、版本和差异名称；不复制任务正文，不补造旧请求未保存的写入过程。同样只允许已登录的登记成员读取。

普通任务的旧修改因版本不同无法继续时，登记成员也可两次点击“以网站设置同步”并确认，采用该操作原先保存的设置。确认绑定操作及当前记录更新时间，重新读取仍未完成且父任务关系未变的原任务后保存新的同步依据；同一请求重放沿用这份依据，不能再次接受后来的冲突设置。已完成、已取消、缺失或已进入协作流程的任务不能借此覆盖；该恢复沿用原操作记录。

## 催办与未读记录

流程建立后，发起方可催办尚未完成或删除的流程，创建中不能催办；认领者可对指定催办回复一次，回复需 1 至 2000 字。催办和回复属于追加记录，不因无关流程版本更新丢失，但仍检查身份、流程状态及回复对象；弹窗提供回复或稍后，保存已读失败时保留弹窗。

审批被打回后，认领者在页面前台收到一次“打回修改”弹窗，显示任务名及该次打回的完整评语和附件；评语、附件未提供时不占用相应位置，图片可沿用现有预览，其他文件可下载。关闭按钮与 Esc 均在服务器保存该次弹窗的关闭状态，保存失败保留弹窗供重试；刷新页面或重新登录不会重复弹出已经关闭的提醒，之后再次打回会重新提示。与催办共用一个弹窗位置，当前提醒处理后再显示下一项，其他设备保存的关闭状态通过通知轮询更新。此前已读的历史打回不补发弹窗，未登录期间的新打回在进入页面后读取。

关闭打回弹窗与阅读任务详情分别记录：关闭仅停止这次弹窗，红点与“有更新”继续保留到详情被查看；从便签、成员任务卡片或流程列表进入同一详情都保存同一份已读记录。打回评语和附件始终保留在流程详情的对应事件中，关闭弹窗或查看详情均不删除历史材料；打回算详情更新，计入主界面任务表角标，但不增加只统计待审批的工作流程入口角标。

任务变化按成员保存未读状态，普通操作人不会收到自己的操作提醒，流程事件提醒面向两位参与者，公共任务提醒面向其他成员。所有成员可查看已显示的流程历史，其中认领记录区分本人认领和安排他人认领；“完成同步”事件不显示，也不制造无法消除的未读提示。自动定位、提前勾选恢复及任务缺失提示不生成常规记录，旧版本同类自动事件也从页面和未读通知中过滤，后台历史继续保留。

流程同步错误独立保存，不计入工作流程事件的未读数量；提醒发送给待同步修改或完成决定的发起者，无这两类依据时使用最近操作人，最后以审批者兜底，因此本人操作失败也能收到提醒。同一次未解决故障沿用相同标识，重试出现不同错误时更新内容，不反复响铃或推送；错误解除后取消对应未读，后续新故障重新提醒。已确认任务缺失仍沿用原有红字提示，不另发同步错误通知。任务板有“同步异常”入口，包含未安排执行和已归档流程的现存错误；未读错误沿用现有页面提示、声音与系统推送渠道，提醒提供“查看错误”和“稍后”，任务板关闭时仍可出现。查看详情中的错误或选择稍后会保存其已读状态，未解决故障仍可从同步异常入口查看。页面发现新错误依赖现有轮询，后台推送依赖已启用的订阅及服务商可用性，不保证所有设备即时收到。

普通任务更新失败同样生成独立同步错误提醒，收件人为该操作发起者，持续失败沿用同一个故障编号；恢复成功或停止重试后对应提醒失效。“查看错误”打开已有待处理操作面板，可继续、停止重试或复制报告，不写入工作流程时间轴。

未认领的公共任务完整可见、页面在前台并停留 1.2 秒后标为已读。流程列表在有未读详情设置修改或审批打回时显示“有更新”，认领、删除、催办和同步错误不替换实际流程状态；没有这两类未读更新时显示已认领、执行中、待审批、已完成或已删除。打开流程详情并在前台显示后，即标记该流程当前记录及来源公共任务的提醒已读，无须逐条滚动到时间轴标记，同时消除本人认领任务的成员卡片和便签上的红点；催办或打回弹窗覆盖期间暂停，服务器确认后清除未读，失败则在后续刷新重试。错误提醒仍独立确认，阅读流程记录不清除现存错误。首次加载旧历史不会批量补发全部旧提醒。

任务板关闭时从错误提醒进入详情，按任务板、流程详情的顺序打开弹窗，避免父弹窗遮住详情；切换指定任务时更新弹窗选择。待确认的同步请求不禁用查看流程和任务详情，也不禁用复制错误报告；会写入任务的控件仍遵守请求状态限制。

页面在前台且未锁定操作时，每 5 秒读取轻量通知和版本；任务板打开后每 15 秒读取完整快照，定时完整刷新在拖动或锁定操作时暂停。轻量响应本身只读取本站记录，完整快照还读取成员收集箱；轻量版本与成员快照可在响应后触发[后台维护](#任务板读取与后台维护)，纯网站记录读取不触发滴答维护，但不会因每 5 秒轮询就同步扫描全部滴答任务，也不会每个请求各启动一轮维护。

## 聊天与语音消息

### 消息发送与历史

聊天支持文字及单个附件，文件按钮选择一个文件，也可粘贴剪贴板中的首个文件；图片在发送前显示预览。Enter 发送，Shift+Enter 换行，中文输入法组合时不会误发，附件上传显示进度。

发送时先显示本地待发送消息，再上传附件并将消息写入服务器，成功后通知在线连接。服务器已确认成功时，实时广播失败不改变发送结果；未确认消息可以使用同一个消息 ID 重试，当前页面会话中已上传的附件可复用。页面刷新后没有保证恢复尚未确认的发送草稿。

首次加载最近 30 条消息，接近顶部时分页加载更早历史；前台目标每 1.5 秒、后台目标每 15 秒同步新增及撤回变化。恢复焦点、网络或页面时取消旧请求并立即补收，墙钟超时避免已挂起请求一直占用同步状态，旧响应不能覆盖新请求。浏览器可以推迟后台定时器，完全冻结时依赖系统推送；后台轮询不是永久保活。用户上翻阅读期间，新消息、本人发送和图片延迟加载保持阅读位置，实际位于底部时才自动跟随；加载早期历史会在内容插入前记录当前位置，避免请求等待期间的滚动被覆盖。

右键或长按提供引用和复制，本人消息还可撤回。撤回接口验证发送者身份，没有按分钟限制；撤回隐藏消息，但不会同时删除附件原文件或已经导入云盘的副本。引用保留发送时的摘录，旧 `imageUrl` 记录继续兼容。图片可在本页查看，关闭查看器恢复焦点与滚动位置，普通文件可下载。

### 录音、播放与转文字

语音录制独立于实时通话，停止并发送或取消由第一次停止决定生效；组件卸载、空录音和录制失败不发送。录制优先采用浏览器支持的 AAC/MP4，再尝试 WebM/Opus 等格式，五分钟或累计 25 MiB 后自动停止，扩展名按真实格式保存。

聊天语音支持播放、暂停及进度拖动，一条新语音开始前会暂停本页另一条语音。用户点击后才请求兼容播放，服务器使用 FFmpeg 生成 AAC 缓存并保留原文件，支持字节范围请求以便移动端拖动进度；转换失败仍可下载原音频。转换队列及运行时间有上限，依赖部署环境中的 FFmpeg 和 FFprobe。

转文字由用户点击触发，当前调用 Cloudflare 的 `@cf/openai/whisper-large-v3-turbo`。服务器校验当前成员、请求来源及语音是否仍为有效已发送消息，转换音频后以 Base64 传给服务，结果保存并供房间成员复用；语音撤回后不再返回其转写。新转写需要账户授权及免费计划确认配置，缺少配置时仍能读取已有缓存。

转写最多接受六个不同待处理任务，外部请求最多三个并行，同一语音合并请求；原音频需在 305 秒以内，转换后不超过 4 MiB。提供方限流或失败时保留重试间隔，由用户再次点击重试，不在后台无限请求，也不保证提供方始终有免费额度。

## 云盘

云盘是同室成员共同访问的服务器目录，没有个人空间隔离。支持新建文件夹及上传文件，可粘贴或拖到当前目录、指定文件夹；不支持直接上传整个本地文件夹。文件夹优先排序，同名上传自动添加编号，不覆盖已有文件；图片可本页查看，其他文件通过浏览器打开或下载。

删除先进入选择模式，再次点击垃圾桶删除所选项目，文件夹包含其全部内容，没有回收站。批量操作逐项执行，成功项从选择中移除，失败项保留供重试；服务器拒绝删除根目录或经过符号链接的路径。

普通聊天文件上传后自动保存到云盘 `chat`，图片和语音通过保存按钮手动导入，分别进入 `chat/pics` 和 `video`。同一附件按 ID 去重，优先使用硬链接，无法建立时复制；删除云盘副本不同时撤回聊天或删除聊天附件原路径。画板保存的 PNG 放到 `board`，已发布任务说明附件放到 `tasks`。

默认云盘额度为 5 GiB，可通过 `CLOUD_DRIVE_LIMIT_BYTES` 修改，达到 90% 或本次写入将超过该阈值时停止写入。额度统计针对云盘目录，聊天原文件、流程提交文件和转写缓存另行占用服务器空间；聊天文件自动导入失败会反馈，但附件本身可能已经上传成功。

## 画板与投影

默认黑板独立保留，最多创建 12 张自定义画板，创建后选中新画板。左右切换按创建时间和 ID 排序，到两端停止；删除当前画板后选择仍存在的前一张，没有前一张则回到默认黑板，可以删除至零张。

画板提供粉笔书写、整笔擦除与局部擦除，可以选择粉笔颜色；文字框支持重新编辑和拖动，四边调整换行范围，四角等比改变框与字号，滚轮调整字号。文字 Enter 确认、Shift+Enter 换行，点击外部也确认，中文输入法组合时保留输入。

新建文字框初始约三个汉字宽、一行高，输入时按文字实际宽度向右扩展，显式换行或到达画板右边缘后自动增高。手动拖动左右边界后使用选定宽度换行，继续输入时按需要增加高度；上下边界、四角缩放和滚轮操作沿用原有行为。自动扩展不改变字号，也不因删除文字自动缩小已扩大的范围；尺寸及自动宽度状态随画板保存与同步，已有文字框保留原尺寸和换行宽度规则。

笔迹与文字按 ID 和版本合并，清屏生成新的 epoch，防止旧快照恢复已清除内容。删除笔迹、文字和画板分别保留删除标记，在线连接建立时交换快照，前台每 10 秒及恢复网络时补充同步；较大的消息分片传输，完整接收后再处理，并有数量与体积上限。

**画板正文目前只在页面内存和在线同伴副本中，没有自动保存为可编辑文件。** 所有持有副本的页面关闭或刷新后，如果没有同伴传回内容，服务器无法恢复正文；服务器永久保存的是已删除画板的 ID，进入页面时先读取，后续定期补读，以防旧画板再次出现。

保存画板会生成长边 1920 像素的 PNG，包括背景、文字及当前笔迹，再上传云盘 `board`；图片不能重新打开为可编辑画板。旧笔迹及旧字体兼容仍保留，新粉笔在显示与导出时使用同一渲染方式。

投影接收屏幕共享或摄像头画面，可以切换来源，屏幕来源优先。收起幕布只改变观看状态，媒体继续连接；共享启停由个人桌面设备控制。主区域支持全屏，F 和 Shift+F 均可切换，编辑输入、中文组合输入或按住 Ctrl、Alt、Meta 时不触发；屏幕共享画面提供画中画入口，摄像头画面没有该按钮，实际使用依赖浏览器支持。

## 实时连接与音视频

当前主页面 `USE_LIVEKIT=false`，实际通过 PeerJS 建立设备间数据和媒体连接。服务端在线列表用于设备发现，设备每 5 秒上报，单台设备最多接入 7 个远端设备；同一成员可以使用多台设备，成员显示与设备连接分别管理。

在线记录保存在服务进程内存中，桌面前台有效期 60 秒，移动或后台设备保留 30 分钟，重启后由设备重新上报。连接中断后的宽限期也会暂时保留设备信息，因此设备仍显示在线不等于后台音视频一定持续传输。

屏幕共享直接打开浏览器选择器，并申请可选音频，没有返回音频也可共享画面。摄像头只申请视频，麦克风由独立开关申请并启用回声消除及降噪；同一身份其他设备传来的麦克风音频在本页过滤，避免听到自己。网站没有将实时投屏或通话录制成文件的功能。

远端音频被浏览器自动播放政策阻止时，先保留画面并提供手动开启。连接恢复会重新挂接或发送已有采集流，不主动重新申请权限；用户或系统已结束的采集不会被自动重新开启。网络穿透依赖 STUN，可配置 TURN 和同源 PeerJS 信令服务器，实际跨网络可用性仍受设备、权限和网络条件影响。

LiveKit 分支与令牌接口仍保留，但当前不属于启用的音视频通道，不能当作已经验证可替换的配置开关。摄像头启动尚无与麦克风同等的请求锁和迟到返回保护，快速连续操作或权限等待期间退出存在生命周期风险；本次无行为变化的清理未改写该流程。

## 摇铃与设备推送

摇铃向另一位成员发起，有效期两分钟，同一发起者与接收者之间的有效摇铃不会重复建立，新建间隔至少 30 秒。发起者可停止，接收者可确认，其他成员不能代为操作；相同请求 ID 可以安全重试。

摇铃状态落盘保存，独立调度器在 Node 服务启动时运行，有效期内按 3 秒间隔申请发送，最多 40 次。服务器先保存发送进度，重启后不集中补发错过的全部次数；页面根据服务器时间计算剩余时间，可见时约每 3 秒读取，后台约每 15 秒读取。

推送需配置成对 VAPID 密钥并由每台接收设备单独订阅。设置 → 消息提醒提供开启、关闭和测试按钮；开启必须由用户点击授权。页面初始化、返回前台及网络恢复时检查订阅有效期和订阅所绑定公钥，并重新保存服务器记录；过期或密钥已变化时提示重新开启，用户开启时重建旧订阅。取消订阅只删除当前身份的记录，浏览器取消失败不能显示关闭成功。订阅及测试接口按反向代理保留的公开 Host 校验请求来源，兼容 HTTPS 在代理处终止；其他站点来源仍被拒绝，不能通过 Forwarded-Host 绕过。

聊天推送排除发送设备及已不在成员记录中的身份，流程通知按参与者范围发送，摇铃只发送到目标身份的订阅设备。聊天通知正文截取 240 个 Unicode 码点，保留服务器消息全文，避免中文、表情或转义字符导致载荷超过 [RFC 8291](https://datatracker.ietf.org/doc/html/rfc8291#section-4) 兼容上限。网络错误、429 与 5xx 最多尝试三次，遵守短期 Retry-After；404/410 回收订阅，其他永久错误不反复重试。日志记录消息 ID、服务商域名、状态及成功/失败数，不记录正文、订阅地址或密钥。当前仍未实现持久推送发件箱，进程重启或持续服务故障期间的提醒不能保证重试到成功，聊天记录仍可补收。

测试提醒只发往当前身份已登记的指定设备，不广播到其他成员。测试结果区分配置缺失、订阅缺失或失效、推送服务拒绝与已接受。服务端接受不证明设备显示横幅、播放声音或震动，仍需检查设备通知权限、通知中心、勿扰及系统后台策略。iOS 主屏幕安装只是使用推送的前提，不代表订阅有效或每次都能即时送达。

聊天通知按消息 ID 使用独立标签，任务按事件 ID、摇铃按提醒 ID 与次数检查当前已展示通知。每个收到的推送事件都调用系统通知展示，遵守 Safari 的可见通知要求；重复事件替换同标签通知且不重新响铃或震动，不再直接丢弃。已过期摇铃保留一条无声历史通知，使用原到期时间、不显示确认正文和操作按钮，返回页面后由摇铃状态查询清理；后台不再立即关闭刚展示的通知。通知查询失败不阻止展示。这份检查没有持久去重账本，通知关闭后不保证永不再次展示。聊天推送还通知正在运行的页面补查。通知点击仅打开同源地址并聚焦房间，“知道了”可直接确认，失败时打开网页继续；Service Worker 没有提供离线页面或文件缓存。

初始化时会核对当前设备的通知权限，权限已撤销时不把残留订阅显示为已开启。用户主动开启时重建现存订阅，即使其本地有效期和公钥未变化，也不继续复用可能已被服务商撤销的地址。新订阅保存时替换同一身份、同一设备编号的旧地址，保留其他设备。设备横幅、声音与锁屏展示仍需 iPhone 实测，Apple 接受回执不作为设备送达证明。Safari 的每次推送展示要求见 [Apple 官方说明](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)。

手机及手表持续震动、远程立即停止和多设备重复提醒仍需远端设备配合验收。相关未完成事项留在需求表，不以本地自动检查替代设备实测。

## 数据保存与运行方式

正式路径使用 Next.js 16 与 Node，容器通过 `npm run build` 生成 standalone 服务，GitHub Actions 构建镜像后部署到现有服务器。持久目录由 `DATA_DIR` 指定，生产默认 `/data`，本地开发默认项目的 `.data`；仓库部署脚本将服务器 `/opt/11scat-data` 挂载为 `/data`，代码更新不会替换这份数据。

| 数据 | 保存位置与用途 |
| --- | --- |
| 身份、活动、小记及座位 | `identities.json`，同时保存加密滴答令牌。 |
| 公共任务、流程与未读 | `room-collaboration.json`，包含操作回执、待恢复进度和已接受但尚未同步完成的决定；旧共享待办另存 `shared-tasks.json`。 |
| 今日任务完成快照 | `classroom-todo.json`，按成员保留当前窗口记录。 |
| 聊天与原附件 | `chat-messages.json` 及 `chat-files`；兼容音频缓存邻接原文件保存。 |
| 云盘及任务说明草稿 | `cloud-drive`，说明草稿另外使用 `task-attachment-drafts`。 |
| 流程提交文件 | `workflow-files`，与说明附件的发布和权限规则分开。 |
| 摇铃、设备推送与转写 | `rings.json`、`push-subscriptions.json`、`speech/transcripts-v1.json`。 |
| 画板与在线状态 | `deleted-boards.json` 只存画板删除 ID；正文与在线设备列表不持久化。 |

多数文件采用临时文件替换及进程内写队列，协作服务通过共享实例避免同一 Node 进程的接口互相覆盖；这不等同于多服务器进程间的数据库事务。当前持久方式依赖可写本地目录，不适合直接多副本横向运行。

身份配置使用 `IDENTITY_CODE_HASHES` 和会话密钥，滴答令牌使用存储密钥加密；实时连接可用 `TURN_*` 和 `PEER_SERVER_PATH`，推送使用 `VAPID_*`，转写使用 Cloudflare 账户、令牌及免费计划确认设置。文档只记录变量用途，不保存实际识别码、访问令牌或服务器密钥；更改加密密钥会影响已有令牌解密，应保留原配置或先制定迁移方案。

仓库还保留 `.openai/hosting.json`、Vinext/Worker 代码、D1 示例与 Render 配置。它们不是当前容器生产启动路径，不能根据这些文件假定网站正在使用 D1、R2 或 ChatGPT 登录，也不能把它们直接当成已验证的部署替代方案。部署与回滚细节见[部署说明](../deploy/README.md)。

## 开发入口与维护边界

开发模式提供 `/classroom-preview`、`/classroom-preview/taskboard`、`/classroom-preview/fonts` 和 `/classroom-preview/chalk-art`，生产环境不开放这些页面。预览用于检查教室、任务板及字库素材，任务数据为样例，部分媒体按钮仍会调用真实浏览器设备选择器；样例交互成功不等于真实双人同步已经通过验证。

当前仍需远端成员配合确认座位变更与离线恢复，以及双人投屏和摄像头、麦克风在各设备上的连续性。双人日历与装饰同步未实现，独立音乐模块已按要求取消；具体未完成功能和线上问题始终查阅[当前需求表](remaining-priority-requirements.md)，本文不复制一套易过期的验收清单。

新增或重绘美术素材继续遵循[教室现行美术参照](classroom-art-reference.md)，以最新已确认的成品外观为依据，先展示预览并取得具体版本同意后才能接入正式素材。功能逻辑变更在同一工作单元更新本文及[功能变更日志](functionality-changelog.md)，使用现有测试核对相关权限与状态转换，并完成生产构建；不要为了减少代码量删去旧任务回执、消息格式兼容或失败恢复。

相关验证入口是 `npm run build`、TypeScript 检查和 `tests` 下的自动检查；音频集成测试还需要 FFmpeg/FFprobe。测试使用隔离数据与模拟滴答接口，能验证代码行为及服务接口，不代表已经操作真实账户或完成远端设备验收。
