# 文档导航

了解网站现行规则时，先读[当前功能说明](current-functionality.md)，查看首次完整说明之后的变化时读[功能变更日志](functionality-changelog.md)；尚未完成的工作以[剩余需求执行表](remaining-priority-requirements.md)为准。历史资料用于查找方案来源及当时的批准范围，其中的“已实现”“待验收”等表述只适用于记录日期。

## 日常维护

| 文档 | 使用场景 |

## 历史归档

[归档目录](archive/README.md)按主题和日期汇总了有保留价值的资料。教室评审的批准范围与素材来源集中记录，任务专题保留设计变化和兼容依据；公开资料调研与实际发布记录各自标明当时的核实范围。

`assets/` 保留历史示意图和独立试写样例，其中的旧配色、布局及按钮不代表当前设计。正式素材的说明及许可证继续放在 `public/` 内，部署操作说明继续放在 `deploy/` 内。

## 后续维护方式

现行功能只维护一份说明，功能变化时在同一工作单元更新对应章节，并向同一份功能变更日志追加记录，简短改动描述仍写入 Git 提交。已有归档不继续追加逐次实施日志；只有新的资料具有独立的来源、许可或长期维护价值时，才新增对应专题并加入本目录。

历史文档中的已取消方案不恢复为待办，旧测试数量也不代表当前版本的验证结果。需要逐字核对旧记录时，通过归档中的固定提交链接查看原文，避免把不同日期的描述混用。
